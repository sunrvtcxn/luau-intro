Roots of Luau / What it is

The Luau you know is a version of Lua 5.1 built upon by Roblox Corporation, which has more features and is faster. Lua was made in Rio de Janeiro / Brazil by the Pontifical Catholic University and is currently being maintained by a team there.
It was designed as a language meant to be efficient, lightweight, embeddable. Hence why many games like Garry's Mod or programs like OBS Studio have plugins / mods with Lua. It's convenient, don't you think?

Luau is backwards-compatible with Lua. This means that most of any code written in Lua will run in a Luau environment. This however doesn't mean that any code written in Luau will necessarily run in a Lua environment,
such as in situations where you use table.find. That doesn't exist in Lua. Additionally, a lot of functions from Lua which may be risky to keep, such as ones which operate on files, are removed in Luau for security reasons.

Let's get this straight: mastery of Lua alone won't make you a god in scripting in Roblox Studio. It's around 50% engine specific methods/functions and around 50% actual Luau code. You will need to learn
a LOT of engine specific things if you want to become a scripter in Roblox, such as what's a Vector3, CFrame, :GetChildren(), and so on. Don't be afraid to look at the official documentation.
Hell, go ahead and watch youtube tutorials to get a general idea of whatever new concept you're trying to grasp. Have Claude, ChatGPT, or Gemini tutor you. Whatever works best for you, learn from that.

Variable Types

Before we start writing actual code, you need to understand all the types of variables you have to your disposal so everything makes sense later on.
Lua has 8 types of variables. A variable stores information. You can declare local variables through typing

local VariableName = VariableData

A number is a number.

local a = 1
local b = 15.5 -- You can also add a period to give more precision / make it a decimal number. This one is referred to as a float.
local c = 2 + 2 -- Math operations are a thing. This will become 4.

A string is a string of characters between quotation marks. Numbers in this context are treated like text.

local a = "did you know this isnt the only way you can declare strings"
local b = 'you can also use this style of "quotation" marks' -- This is a thing in order to prevent issues where a string contains another quotation mark of the same type. You wouldn't know either where the string actually ends.
local c = "1" -- Math operations in some cases will work as they for that operation get automatically converted to a number, however I would personally refrain from operating on strings for math.

A nil represents nothing.

local a = nil -- It can be used in situations where, for example, it's necessary that you first declare a variable then change it accordingly.
local b -- This is another way to declare a nil variable.

A boolean represents true or false. Alternatively, true is 1 and false is nil.

local a = true
local b = false -- Zero will evaluate to true which shouldn't happen in context of false, therefore false is really nil instead of a 0 unlike in many other programming languages.

A table is a collection of multiple variables. Each entry has a key and value. The key defines the "identifier" of the value by which you can access it, whereas the value is simply the held variable.
The key can be anything (for the most part), you can manually define one. If you don't, the next available number will be assigned by default instead.

local a = {
    [1] = 'kevin',
    ['hello'] = 91,
    'apple',
    {'tables inside tables can exist btw'},
    function()
        print("even functions!")
    end,
}

print(a.hello) -- prints 91 / This is one way to get the value from a key.

A function represents a function. It can accept arguments which allow for great flexibility. It can return processed arguments with return.
This is especially useful if you need to repeat something multiple times in order to avoid harder to maintain and generally unreadable code.

local function pow(num, amount)
    return math.pow(num, amount)
end -- This is a very useless function, but I'm just using this as a demonstration.

print(pow(2, 5)) -- prints 32

There are 2 other types. Userdata and threads. I will skip them, as for now you don't necessarily need to know what those are. Sorry not sorry.

First Steps

Open up Roblox Studio and create a new script anywhere. Most often you'll put one inside ServersideScriptService.
Let's learn some fundamentals.

print, as demonstrated earlier, allows you to print whatever. You can directly insert a string, and it will print a string. You can directly insert a number, and it will print the number. You'll mostly use for checking if everything is alright or for debugging purposes.

print("Goodbye, World!") -- prints Goodbye, World!

local a = 1
local b = "hello"
local tab = {'hi', 'yup'}
print(a) -- prints 1
print(b) -- prints hello
print(tab) -- prints {'hi', 'yup'}. You might need to expand it to see it properly in the output tab. If you print this from an argument, you won't get the table's contents printed, but instead the memory address of the table, ex. 0x7ffe5367e044.

Let's do something with a part. Go ahead and insert one into your place. Rename it to whatever you want or "kevin" if you want to very strictly abide by the next instructions.
Let's now get the part into a variable. game.Workspace or simply workspace's general purpose is holding parts that will be physically present in your game.

local part = workspace.kevin

Let's make it invisible. You can change the properties through things by accessing them in the following manner. Keep proper capitalisation in mind, otherwise the script might error.

local part = workspace.kevin
part.Transparency = 1

-- You don't need to operate on the part through a variable. You can also operate on the part directly.
-- workspace.kevin.Transparency = 1

Now run the game, and it should look like it's gone. It's still there, just invisible. You can modify other properties in a similar fashion. Let's now paint it red and make it move by 5 studs along the Z axis in game.

local part = workspace.kevin
part.Color = Color3.fromRGB(255, 0, 0)
part.Position = part.Position + Vector3.new(0, 0, 5) -- It's a good time to mention that you don't have to type all that. You can also do part.Position += something or part.Position -= something. Same goes with variables and other things that involve numbers.

You get the gist. Some properties will need a unique way to be handled as shown in this example. Refer to Google or documentation.
